# AI Debug — 로컬 제품 기획

기준일: 2026-09-14. 이 디렉토리는 로컬 제품의 계약이다. 현재 실행 기준은 **프로젝트별 작업 범위·독립 Git worktree·Docker 실행·네트워크 허용**이다. 과거 네이티브 프로세스 이탈 검사는 신규 실행의 선행 조건이 아니다. 실행 절차는 [운영](operations/README.md), 확인한 범위는 [검증 기록](operations/verification.md)을 따른다. 기존 `devauto` 프로토타입은 새 계정 앱의 실행 경로가 아니다.

## 1. 목적

관리자가 Mac에서 실행한 웹 앱을 통해 비개발 매니저가 문제를 설명하고, 요구사항을 확인한 뒤, Codex에 코드 수정을 맡긴다. 매니저는 결과를 확인해 재수정 또는 작업 완료를 선택하고, 관리자는 완료 확인된 로컬 결과를 자신의 앱 계정으로 승인한다. 원격 발행은 별도 설정과 승인 후 수행한다.

성공 기준은 프레임워크를 갖추는 것이 아니라 **등록된 실제 로컬 프로젝트 하나에서 요청 → 분석·명세 확인 → 수정·검증 → 사용자 결과 확인·재수정 → 관리자 로컬 승인이 끝까지 동작하는 것**이다. 원격 발행을 설정한 프로젝트에서만 별도 발행 승인 → 새 브랜치 push → GitHub Draft PR까지 이어진다.

로컬은 서버·작업 파일·업무 기록이 관리자 컴퓨터에 있다는 의미다. Codex 추론에는 인터넷과 기존 Codex 이용 권한이 필요하고 선택한 코드·요청이 제공자에게 전달될 수 있다. 오프라인 AI를 의미하지 않는다.

## 2. 확정된 범위

| 항목 | 이번 제품의 결정 |
| --- | --- |
| 웹 앱 | Python, Django 풀스택, 서버 렌더링 화면 |
| 실행 위치 | 관리자 Mac, 로컬 Git 저장소의 독립 작업 사본 |
| AI | [ai](ai/README.md) | 기존 Codex 로그인, 명시적 모델·effort, Docker 작업 실행 |
| 실행 방식 | 독립 Git worktree와 로컬 Docker 컨테이너 안에서 Codex 내장 도구 사용; 외부 네트워크 허용 |
| 모델 | 호출마다 모델·effort 명시, 대화와 코드 수정 프로필 구분 |
| 권한 | ADMIN/MANAGER 앱 계정과 프로젝트 소속으로 판정 |
| 발행 | ADMIN만 승인·실행, 승인되지 않은 push/PR 불가 |
| 기기 | 휴대폰·PC·localhost·IP는 권한 근거가 아님 |
| 접속 | 같은 PC에서 기본 기동, 신뢰된 같은 네트워크 접속은 관리자가 HTTPS를 설정한 경우에만 허용 |
| 결과 | 변경 요약, 파일별 diff, 검증 증거, 다운로드 가능한 로컬 패치 |
| 원본 보존 | 원본 저장소의 브랜치·미커밋 변경·untracked 파일을 수정하거나 정리하지 않음 |

클라우드 배포, AI API 직접 연동, Claude, 도구 없는 모델 드라이버, 자체 범용 실행 프로토콜, 제공자 추상화는 설계 대상에서 제외한다. Docker는 현재 로컬 실행 경계이며 별도 원격 러너 서버를 만들지 않는다. GitHub 발행은 관리자 계정의 별도 승인 후 수행한다.

## 3. 매니저가 보는 제품

헤더 메뉴 순서는 `Project / Request / AI / Admin / Docs / Account`다. `AI`와 `Admin`은 관리자에게만 표시하고, `Docs`는 문서 아이콘, `Account`는 설정 아이콘으로 표시한다. 매니저의 메뉴는 `Project / Request / Docs / Account`다. `Docs`는 이 서비스의 한국어 사용 가이드이며 이 저장소의 개발 기획서를 공개하는 메뉴가 아니다. 화면 경로·역할·활성 메뉴·공통 레이아웃의 단일 기준은 [내비게이션과 사용 가이드](navigation/README.md)에 둔다.

1. `Project`에서 프로젝트를 고르고 `문제 상담·내 요청`을 연다. “무엇이 문제인지 / 무엇을 바꾸고 싶은지” 입력하고 `대화 시작`을 누른다.
2. 필요한 경우에만 재현 방법·기대 결과·화면 자료에 관한 짧은 질문에 답한다.
3. AI가 정리한 변경 범위와 완료 기준을 읽고 `이 명세로 준비`로 확인한 뒤 `수정 작업 시작`을 누른다. 명세 확인만으로 수정이 시작되지는 않는다.
4. `대기 중 / 수정 중 / 검증 중` 등 실제 저장 상태를 확인하고 필요하면 취소한다.
5. `Request`에서 자신의 요청·실행을 다시 열고, 결과에서 바뀐 점·확인된 점·남은 문제를 읽거나 패치를 받는다. 원격 발행이 필요하면 관리자에게 검토를 요청한다. 앱의 발행 검토 준비·승인 버튼은 관리자에게만 제공한다.

매니저에게 저장소 경로, CLI 옵션, 모델 ID, effort, 시스템 프롬프트, 샌드박스, 세션 ID, Git 자격 증명을 입력하게 하지 않는다. 관리자의 프로젝트 설정은 `Project` 안에, AI 연결·모델 설정은 `AI`에 둔다. `Admin`에는 `요청 승인`, `계정 관리`, `운영 상태` 진입점을 모은다. 요청 승인은 사용자 확인을 마친 로컬 결과와 선택적 원격 발행을 구분해 다룬다. 명세 확인이나 로컬 수정 시작에 관리자 승인을 요구하지 않는다.

모든 화면은 Header(로고·메뉴), Navigation(현재 위치·연결된 경로), Notification(메시지가 있을 때만), Main(본문), Footer(작은 저작권·외부 프로필 링크)로 구분한다. 헤더와 네비게이션은 간격을 좁히고 배경색으로 구분한다. 로그아웃은 헤더에 두지 않고 `Account` 화면의 본문 맨 아래에 작은 버튼으로 둔다.

Bot·메모리·툴·스킬을 각각 독립 설정 메뉴로 만들지 않는다. 제품의 도우미는 대화에 고정된 역할로 나타나며, 대화 내용·확정 명세·결과가 지속성을 제공한다. 범용 장기 메모리나 사용자 정의 에이전트 플랫폼은 만들지 않는다.

공통 용어는 [CONTEXT](CONTEXT.md)에 둔다. 하나의 사실에는 하나의 소유 도메인만 둔다. 예를 들어 Run 성공은 실행이, 발행 성공은 승인·발행이 결정한다. AI 메시지는 둘 중 어느 상태도 확정할 수 없다.

## 5. 구현 기본값과 변경 규칙

아래는 추가 사용자 결정을 기다릴 필요 없이 적용할 **가역적 구현 기본값**이다. 확정된 제품 목적·권한 원칙을 바꾸는 결정과 구별한다.

- macOS, Python 3.11 이상, Django 5.2 LTS의 지원 중인 보안 패치 버전, SQLite.
- Django 웹 프로세스와 같은 프로젝트의 `process_jobs` 관리 명령. HTTP 요청에서 CLI 완료를 기다리지 않는다.
- 대화 슬롯 1개, 수정·검증·발행 공용 실행 슬롯 1개. 별도 Redis/Celery 서비스 없음.
- 원격 발행 기본 비활성. 관리자가 GitHub 대상 저장소·기준 브랜치·인증을 설정하면 활성화한다.
- 수정 작업의 필수 검증 명령 1개 이상. 미설정·미실행·건너뛴 검증을 성공으로 표시하지 않는다.
- 모델 프로필은 관리자만 변경한다. 실제 수정 기본 후보는 `gpt-6-astra / xhigh`, 상세한 지원 확인은 AI 문서를 따른다.

기본값을 바꾸면 해당 도메인의 결정 ID와 수용 기준을 함께 수정한다. 프로젝트 실행 설정 변경은 `project_config_version`, 발행 설정 변경은 별도 `PublicationPolicy.version`을 증가시킨다. 발행만 처음 활성화했다고 같은 코드·검증 결과를 다시 만들 필요는 없으며 새 발행 대상에는 별도 승인이 필요하다. 실행 중인 작업에 설정을 소급 적용하지 않고, 외부 영향·권한 범위가 달라지는 선택은 자동으로 확대하지 않는다.

## 6. 문서의 지위

- 이 문서와 각 도메인의 결정·수용 기준이 현재 구현 기준이다. 충돌하면 이 문서의 범위·계정 권한 원칙을 먼저 적용하고 도메인 문서를 정정한다.
- [후속 기능 TODO](todo/README.md)는 조사·제안·미결정 사항을 보관한다. 현재 구현 기준이나 구현 완료 목록이 아니며, 승인된 내용만 해당 도메인 문서로 반영한다.
- `docs/operations/implementation.md` 체크리스트는 구현 증거가 생긴 뒤에만 완료 표시한다.
- 전체 문서 교차 검토의 수정 사항과 구현·문서 커밋 판단은 [구현 문서의 기획 검토](operations/implementation.md#5-기획-검토와-구현커밋-판단)에 기록한다.
- 이전 `docs` 전체는 `.docs/backup`에 원문 보존했다. 수정 전 참고 자료이며 새 구현의 규범이나 필수 읽기 목록이 아니다.
- `.docs`는 Git 제외 경로이므로 백업은 이 작업 공간에만 있다. Git으로 배포되는 새 문서가 백업에 의존해서는 안 된다.
- 문서 날짜·CLI 도움말 확인·프로토타입 테스트 성공은 새 제품의 작동 또는 안전성 검증을 대신하지 않는다.
