## 관리 방식

- 사용자 요구, 현재 구현에서 확인한 사실, 권장 설계, 미결정을 구분한다
- 조사에는 확인 날짜와 코드·외부 자료의 출처를 기록한다
- 구현 전 필요한 질문은 Y/N 권장안과 대안의 차이를 함께 적는다
- 실제 결정 후 [현재 도메인 문서](../README.md)에 반영한다. TODO만으로 구현을 승인하거나 기존 계약을 대체하지 않는다
- 구현 완료는 코드·마이그레이션·테스트·브라우저 검증 근거와 함께 표시한다
- 이번 문서는 로컬 Django·Codex·Docker 흐름의 확장만 다룬다. 클라우드·AI API 직접 호출·Claude 지원을 추가하지 않는다
