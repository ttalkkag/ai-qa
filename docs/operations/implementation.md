# 구현 순서와 완료 판정

이 체크리스트는 로컬 제품 전체의 완료 기준이다. 2026-09-11에 Django 구현과 자동·브라우저·운영 검증을 진행했으며, 정확한 증거와 남은 구현은 [현재 검증 기록](verification.md)에 구분한다. 일부 조건만 입증한 복합 항목은 완료로 체크하지 않는다. 2026-09-14부터 실행 기준은 독립 Git worktree·Docker·네트워크 허용으로 변경되었다. 과거 네이티브 검사 결과를 신규 실행의 선행 조건으로 적용하지 않는다. 제품 범위는 [기획](../README.md), 기동 절차는 [운영](README.md)을 따른다.

## 1. 현재 코드에서 확인한 출발점

| 현재 코드 | 참고할 수 있는 부분 | 새 구현에서 반드시 달라지는 부분 |
| --- | --- | --- |
| `devauto/api/main.py` | 요청 입력·상태/결과 조회 흐름 | shared token 대신 Django 계정·소유권·CSRF·화면 |
| `devauto/core/models.py`, `db.py`, `state_machine.py` | 작업 기록·상태 전이 경험 | 명세/Run/AIInvocation/Approval/Publication을 분리한 ORM과 transaction |
| `devauto/core/project_config.py` | 프로젝트 설정·검사 목록 | 관리자 소유의 로컬 repo·불변 설정 버전·argv 명령 |
| `devauto/runner/workspace.py`, `subprocesses.py`, `worker.py` | workspace·프로세스 정리·작업 claim | 원본 보존, 단일 worker/slot, lease·자손 종료 증거 |
| `devauto/runner/ai_cli.py`, `context.py` | CLI 메시지·문맥 처리 | Codex만 사용, 매호출 모델/effort·개인설정 배제·native 권한 검증 |
| `devauto/runner/gates.py`, `artifacts.py` | 검사와 파일 결과 개념 | baseline/after 실제 증거, 누락/skip 비통과, 불변 결과 hash |
| `devauto/runner/reviewer.py`, `publisher.py` | 검토·발행 흐름 | AI 판정은 자문, ADMIN 승인 결속, 신뢰된 결과에서 신규ref만 발행 |

기존 모듈을 새 이름으로 옮겼다는 이유만으로 재사용을 확정하지 않는다. 새 계약과 동일한 동작은 테스트로 확인해 재사용하고, 보안/도메인 계약이 다른 부분은 교체한다. 기존 원격 배포·다중 CLI 지원은 새 흐름에 연결하지 않는다. 기존 데이터 자동 마이그레이션은 구현 필수 범위가 아니며 기존 prototype DB를 새 DB로 덮어쓰지 않는다.

## 2. 사용자 흐름을 잇는 구현 순서

| 순서 | 구현 범위 | 확인 가능한 완료 증거 |
| --- | --- | --- |
| 1 | Django 기동·계정·프로젝트 등록·관리자 화면 | 두 계정의 로그인/역할/소속 분리, 원본 repo 무변경 |
| 2 | 기존 Codex 연결·프로필·Docker 환경 점검 | 모델 없는 canary 통과 후 제한된 실제 호출, 로그인 재사용·모델·effort 기록 |
| 3 | 매니저 대화·명세 준비·명시적 제출 | 화면의 SHA·설정·초안과 확정 명세 일치, 기준 갱신 복구, 중복 제출에 Run 1개 |
| 4 | worker·독립 사본·수정·기준/변경 후 검사 | 원본 보존, 숨긴 원본 파일 복원, 고정 후보를 독립 환경에서 검사한 hash와 결과 hash 일치 |
| 5 | 결과 UI·패치 다운로드·취소·재시도·중단 복구 | 비개발자 설명과 diff 일치, ACL·자손종료·멱등성 검증 |
| 6 | 관리자 승인·조건부 새 브랜치·GitHub Draft PR | 결과·실행 설정·발행 정책·대상 결속, MANAGER 거부, 원격 효과별 실패·부분 완료·불명 구분 |
| 7 | 설치·운영·선택적 LAN·백업/복구 정리 | 잠긴 의존성 설치, 두 계정 UX, 모든 writer 중지 백업, 복원 후 옛 Job 자동 실행 없음 |

2번에서 Docker 연결·작업 마운트와 기존 로그인 재사용을 확인하고 실제 모델 시험을 진행한다. 실행 환경 오류를 호스트 직접 실행으로 대체하지 않는다.

## 3. 검증 경계

### 앱·도메인 자동 검사

- [ ] accounts: ADMIN/MANAGER·멤버십·owner별 목록/상세/파일/POST 접근, 마지막 ADMIN 보호, 정지 즉시 반영, 서버의 절대 세션 만료.
- [ ] projects: 경로 우회·금지 파일·실행 설정 revision과 발행 정책 version 분리, dirty 원본 보존, argv·출력 경로 검증, 테스트 0/skip/unknown 처리.
- [ ] conversations/requests: 다른 사용자의 문맥 배제, 채팅과 승인 구분, 표시한 SHA·설정·초안의 확정·멱등성, 본문 변경 없는 기준 갱신, 중복 제출·명시적 retry.
- [ ] runs: 원자적 claim, 중복 worker, lease 만료, Run 없는 Job도 process identity 추적, timeout/취소/재시작, slot 복구, 독립 AFTER 환경·소스 불변성·새 JUnit 증거.
- [ ] ai: model/effort 전달, no fallback, JSONL·quota·timeout·구성 오류, prompt injection으로 권한 확대 불가.
- [ ] artifacts: 경로 우회·심볼릭 링크·비밀 후보·용량 초과, 검사 후보와 봉인 결과 hash 일치, 필수 증거 유실과 보조 로그 정상 만료 구분, 비공개 다운로드.
- [ ] approvals: stale 승인·동시 승인·계정/정책 변경, 신규ref 경쟁과 base 이동, UNKNOWN/PARTIAL 대조, 다른 ADMIN의 남은 PR 재승인, 명시적 포기와 pin 해제, 재시도 중복 방지.
- [ ] operations: loopback/HTTPS 모드 분리, Host/Origin/CSRF, 설정 오류, 공간 부족, 일관 백업과 복원 시 과거 실행 권한·대기 Job 무효화.

### 실제 로컬 통합 검사

- [ ] 임시 Git fixture에 작은 결함과 통과/실패를 구별할 수 있는 검사를 준비한다. 실제 사용자 원본에 고의 결함을 만들지 않는다.
- [ ] 기존 Codex 로그인·선택 모델로 요청 구체화와 실제 수정이 각각 성공한다. CLI 도움말·mock 출력으로 대체하지 않는다.
- [ ] Docker에는 작업 사본만 제공하고 원본·DB·호스트 홈·Docker 소켓을 마운트하지 않는다. 컨테이너 파일 쓰기와 외부 네트워크 접근을 실제 확인한다.
- [ ] 필수 검사 실패/0개/생략/환경 부재에서는 성공·발행이 차단된다. lint 성공을 테스트 성공으로 부르지 않는다.
- [ ] 작업 중 취소, 브라우저 종료, worker 강제 종료, 재기동으로 자손·중복 실행·stale lease를 확인한다.
- [ ] 결과 diff와 patch 적용 결과가 일치하고 원본의 HEAD/index/dirty/untracked 내용이 시작 전과 같다.
- [ ] Codex가 준비 환경을 바꾸거나 검사 명령이 소스를 수정하려는 fixture에서도 고정 후보와 실제 검사 대상이 바뀌지 않는다. 오래된 JUnit·수정된 테스트 자체를 신뢰성 증명으로 오인하지 않는다.

### 브라우저·계정 검사

- [ ] ADMIN과 MANAGER의 별도 브라우저 세션으로 실제 사용자 흐름을 수행한다.
- [ ] 매니저가 프로젝트·문제·명세만으로 수정과 결과 확인을 완료하며 CLI·모델 설정을 입력하지 않는다.
- [ ] 매니저는 승인 버튼을 볼 수 없고 직접 POST해도 발행 부작용이 없다. 관리자도 로그인·CSRF 없이는 거부된다.
- [ ] 계정 정지/멤버십 회수 후 이미 열어 둔 화면의 polling·다운로드도 거부된다.
- [ ] 다른 기기를 사용할 때 역할은 그대로이고 활성화하지 않은 LAN·평문 HTTP 경로는 차단된다.

### 선택한 GitHub 발행 검사

원격 쓰기는 관리자가 지정한 검증용 repo와 명시적 승인 안에서만 시험한다. 문서 작성이나 일반 `make check`가 실제 push/PR을 발생시키면 안 된다.

- [ ] 미승인/MANAGER/stale 결과에는 push가 발생하지 않는다.
- [ ] 승인된 결과만 새 브랜치에 한 번 생성되고 Draft PR의 head/base/commit이 결속값과 일치한다.
- [ ] 동명 ref 경쟁에서 기존 ref를 수정하지 않으며 base 변경을 감지한다.
- [ ] push 성공 뒤 PR 실패, timeout 뒤 실제 원격 성공을 각각 재현하고 중복 발행 없이 대조한다.
- [ ] push/PR 사이 base 이동·승인자 권한 회수는 실제 변경을 보존하며 중단한다. 남은 PR 재승인은 조건을 충족한 활성 ADMIN만 할 수 있다.
- [ ] 원격 발행을 설정하지 않은 프로젝트도 로컬 결과 저장·다운로드까지 사용할 수 있다.

## 4. 완료 보고 형식

각 증거에는 구현 commit 또는 작업 tree 식별값, OS·Python·Django·Codex 버전, 모델·effort, 검사 명령/환경, 실제 결과, 미검증 경계를 기록한다. 비밀값·인증 원문은 기록하지 않는다.

| 경계 | 결과 표기 예 |
| --- | --- |
| 문서·정적 검사 | 링크/형식 확인, 제품 실행은 미검증 |
| 자동 테스트 | pass/fail/skip 수와 실행한 범위 |
| 실제 Codex | 요청한 model/effort와 성공/실패·미보고 값 |
| Docker 실행 | 작업 마운트, 실제 파일 변경, 네트워크 허용, 원본 보존 결과 |
| 브라우저 | 사용한 계정/흐름·성공과 미실행 화면 |
| GitHub | 승인된 repo·branch·commit·PR 결과, 또는 미실행 |

“로컬에서 사용 가능”은 실제 통합·계정 UI·운영 복구를 포함한 결과다. “발행 가능”은 원격 검증까지 별도 확인한 결과다. 테스트 mock만 통과했거나 문서만 작성했을 때 어느 표현도 사용하지 않는다.

## 5. 기획 검토와 구현·커밋 판단

이 절은 코드 구현 전에 수행한 기획 검토의 역사적 기록이다. 이후 구현·실행 결과나 현재 커밋 권한을 뜻하지 않는다. 현재 구현 작업에서는 커밋·push를 하지 않았다.

2026-09-11에 전체 도메인과 현재 코드·설정·CLI 계약을 대조했다. 아래 논리 충돌을 고쳤으며, **이 문서를 기준으로 구현을 시작하고 기획 문서만 커밋해도 되는 상태**로 판단한다. 사용자에게 추가로 범위 선택을 요구할 미결정 사항은 발견하지 못했다. 이는 새 제품의 구현 완료나 실제 실행 안전성 승인이 아니다.

| 검토에서 수정한 문제 | 확정한 계약·소유 문서 |
| --- | --- |
| 화면에서 확인한 기준과 다른 명세 확정, 본문을 고쳐야만 stale 상태 복구 | 초안·설정·SHA를 함께 비교하고 기준 갱신을 독립 동작으로 제공 — [요청](../requests/README.md) |
| 발행 설정을 켜는 것만으로 정상 로컬 결과 무효화 | 실행 설정과 발행 정책 버전을 분리하고 새 대상만 재승인 — [프로젝트](../projects/README.md), [승인](../approvals/README.md) |
| 숨긴 파일이 삭제로 반영되거나 검사 뒤 다른 코드가 결과로 봉인될 여지 | 전체 기준 트리에 허용 변경을 합친 후보를 고정하고 독립 AFTER 환경·읽기 전용 소스·동일 hash로 검사와 봉인 결속 — [실행](../runs/README.md), [결과물](../artifacts/README.md) |
| Codex가 바꾼 검사 환경·오래된 보고서 재사용, 보조 로그 정상 만료를 결과 손상으로 오인 | 별도 검증 환경·새 보고서, 필수 증거와 만료 기록 분리 — [프로젝트](../projects/README.md), [결과물](../artifacts/README.md) |
| 승인자 회수 후 복구 불가, base 경합·인증 오류를 원격 효과와 다르게 기록 | 남은 PR만 새 관리자 승인, 최종 관측과 원격 잠금 구분, FAILED/PARTIAL/UNKNOWN을 실제 증거로 판정 — [승인](../approvals/README.md) |
| 백업 중 웹 쓰기·복원된 대기열 재실행, 잠금 파일 없는 설치·불완전 LAN 기동 | 전체 writer 중지 백업, 새 instance에서 옛 실행 권한 무효화, locked 설치와 안전한 기동 거부 — [운영](README.md) |
| CLI sandbox 옵션 혼용·모델 시험 선행, 브라우저 종료를 확정 로그아웃으로 가정 | 로컬 도움말에 맞는 옵션과 canary 선행, 서버 기준 세션 만료 — [AI](../ai/README.md), [계정](../accounts/README.md) |

남은 전체 인수 조건은 실제 매니저 요청부터 결과 생성까지의 통합 흐름, 강제 중단 복구와 승인된 GitHub 발행이다. 작은 모델 호출·수정 시험의 성공은 전체 완료와 구분한다. Docker 미준비 시 호스트에서 대신 실행하지 않는다.

문서 커밋 범위는 루트 `README.md`, 새 `docs/**`, 이전 문서 이동으로 생긴 `docs/plan`, `docs/research`, `docs/report.md` 삭제다. `.docs/backup`은 로컬 보존 자료라 강제 추가하지 않는다. 기존 별도 변경인 `AGENTS.md`, `Makefile`, `package.json`, `package-lock.json`, `review-agent.md`는 이 기획 검토의 커밋 대상이 아니다. 비활성(`enabled: false`) 문서 동기화 hook의 과거 문서 경로도 이번 수정 범위에서 보존했으며, 재활성화할 때 새 경로·실제 구현에 맞춰 정정한다.

이번 검토 작업은 기획 문서 수정만 수행하며 실제 코드 구현·staging·commit·push를 포함하지 않는다. 현재 프로토타입의 테스트 결과는 새 제품 체크리스트를 완료 표시하는 근거로 사용하지 않는다.
