1. 프로젝트 선택과 화면 이동

관리자에게 받은 계정으로 로그인하세요. 초기 비밀번호 변경 안내가 나오면 먼저 비밀번호를 바꾼 뒤 다시 로그인하세요.

Project에서 작업할 프로젝트를 선택하고 문제 상담·내 요청을 누르세요. {% if can_manage %}프로젝트가 없다면 아래 관리자 등록 안내를 따라 첫 프로젝트를 등록하세요.{% else %}프로젝트가 없다면 관리자에게 계정의 프로젝트 할당을 요청하세요.{% endif %} 보관된 프로젝트는 과거 대화·요청만 볼 수 있습니다.

상단 헤더의 Request에서는 내 요청을 다시 찾을 수 있습니다. Docs는 사용 가이드, Account는 내 계정입니다. AI와 Admin 메뉴는 관리자에게만 표시됩니다.

헤더 아래 네비게이션은 현재 위치와 상위 경로를 보여줍니다. 경로 이름을 누르면 해당 페이지로 이동합니다. 로고를 누르면 Project로 돌아갑니다.

2. 문제 설명과 대화

새 대화에 질문이나 바라는 결과를 적고 대화 시작을 누르세요. “어느 화면에서, 무엇을 했을 때, 지금 어떻게 되며, 어떻게 바뀌면 좋은지”를 구체적으로 적으면 도움이 됩니다.

예: “게시판에서 제목으로 검색하면 관련 없는 글도 표시됩니다. 검색어가 제목에 포함된 글만 보이게 해 주세요. 검색어가 없을 때는 기존 목록을 유지해 주세요.”

답변을 보고 필요한 내용을 설명 보내기로 보완하세요. 필요하면 화면 자료 또는 로그 첨부에서 파일을 선택하고 첨부 준비를 누르세요. 준비가 완료된 파일은 다음 설명을 보낼 때 함께 전달됩니다.

입력한 코드·자료는 호스트에 로그인된 Codex를 통해 외부 모델로 전달됩니다. 비밀번호, 토큰, 개인정보는 입력하거나 첨부하지 마세요. 메시지를 보내는 것만으로 코드 수정이나 발행이 시작되지는 않습니다.

수정할 내용을 정리할 준비가 되면 요청으로 정리를 누르세요.

3. 요청 명세 확인과 수정 시작

  1. 목표, 현재 동작, 기대 동작, 재현 방법, 완료 조건, 수정 범위 등을 확인하고 초안 저장을 누르세요. 완료 조건은 결과를 보고 확인할 수 있는 문장으로 한 줄에 하나씩 적습니다.
  2. 정리가 어렵다면 저장한 내용으로 AI 제안 받기를 사용할 수 있습니다. 제안은 검토 후 이 제안을 초안에 반영해야 적용됩니다.
  3. 저장된 명세를 확인한 뒤 이 명세로 준비를 누르세요. 아직 해결하지 않은 필수 질문이 있거나 프로젝트 준비가 부족하면 먼저 안내된 항목을 해결해야 합니다.
  4. 준비가 완료되어 버튼이 나타나면 수정 작업 시작을 누르세요. 이때 확인한 명세로 코드 수정이 시작됩니다.

초안 저장과 명세 준비만으로는 코드를 수정하지 않습니다. 수정은 원본의 커밋된 코드에서 만든 별도 작업 사본에서 진행하며, 원본의 미커밋 변경은 작업 입력에 포함하지 않습니다.

작업을 시작한 후 초안이나 대화에 내용을 추가해도 이미 실행 중인 작업의 명세는 바뀌지 않습니다. 다른 요구사항으로 작업하려면 명세를 다시 확인하고 새로 실행하세요.

4. 진행 상태와 문제 대응

Request에서 요청을 열고 확정 명세와 실행 이력의 실행 링크로 진행 상태를 확인하세요. 실행 화면의 단계와 메시지는 자동으로 갱신됩니다.

  • 중단하려면 실행 화면의 취소 요청을 누르고, 취소가 완료되었는지 상태를 확인하세요.
  • 실패하거나 차단되면 화면의 상태·오류 메시지를 확인하세요. 프로젝트 준비, AI 연결, 권한 또는 실행 환경 관련 안내는 관리자에게 해당 요청과 함께 전달하세요.
  • 새 실행으로 재시도는 같은 명세로 새 수정 작업을 실행합니다. 이전 작업의 단순 재개가 아니며 결과가 달라질 수 있습니다.
  • 대화의 답변 요청이 실패하여 답변 다시 요청이 보이면 해당 버튼으로 다시 요청할 수 있습니다.

5. 변경 결과와 발행

실행 화면의 결과 확인에서 요청과 변경 요약, 파일별 변경, 실제 검증 결과를 확인하세요. 사용 가능한 패치와 결과 자료는 검증과 패치 영역의 링크로 내려받을 수 있습니다.

완료는 검증된 로컬 결과가 만들어졌다는 뜻이며, 원격 저장소 반영이나 배포 완료가 아닙니다. 기대한 완료 조건을 충족하는지 직접 확인하세요.

결과가 맞으면 작업 완료 · 관리자에게 전달을 선택하세요. 보완이 필요하면 재수정 요청에 내용을 적고 새 명세를 확인합니다. 기존 요구사항과 보완 내용을 기준 코드에서 새로 실행하며 이전 결과는 보존됩니다.

관리자는 사용자가 확인한 결과를 Admin → 요청 승인에서 승인하거나 보완 요청합니다. 로컬 승인은 push·PR을 실행하지 않습니다. 원격 발행은 별도 설정·검토·승인이 필요하며 매니저에게 발행 권한은 없습니다.

결과가 제한되거나 손상·만료되었다는 안내가 나오면 다운로드나 발행을 계속 시도하지 말고 관리자에게 문의하세요. 비밀정보 의심으로 제한된 결과는 안전한 입력으로 새 작업을 요청해야 합니다.

6. 계정과 로그아웃

헤더의 설정 아이콘 Account에서 본인의 아이디를 확인하고 닉네임을 수정한 뒤 내 정보 저장을 누르세요. 아이디는 로그인에 사용하며 이 화면에서는 변경하지 않습니다. 닉네임은 아이디와 별개이고 이메일은 사용하지 않습니다. 다른 사용자 관리나 프로젝트 할당은 이 화면에서 변경하지 않습니다.

비밀번호 변경에서 현재 비밀번호와 새 비밀번호를 입력하세요. 현재 로컬 서비스의 비밀번호는 6자 이상입니다. 변경 후에는 새 비밀번호로 다시 로그인해야 합니다.

사용을 마치면 Account 화면 가장 아래의 로그아웃을 누르세요. 계정 비밀번호를 잊었다면 관리자에게 재설정을 요청하세요.

7. 관리자: 프로젝트 등록과 준비

등록 전 준비

서버 PC에 Git 저장소와 커밋된 코드가 있어야 합니다. GitHub URL이 아닌 로컬 최상위 폴더를 등록합니다. 다른 PC의 브라우저를 사용해도 코드 경로는 서버 PC 기준입니다.

예시 경로를 그대로 입력하지 말고 실제 폴더 경로로 바꾸세요. 원격 저장소만 있다면 먼저 서버 PC에 내려받아야 합니다.

  • macOS: /Users/your-name/Projects/sample-board
  • Windows: C:\Users\your-name\Projects\sample-board

프로젝트 등록

Project 첫 화면의 프로젝트 추가를 누르세요. 이미 프로젝트가 있다면 목록 네비게이션 우측의 Add를 사용합니다.

  1. 프로젝트 추가에서 알아보기 쉬운 이름을 입력하고, 필요하면 설명을 적습니다.
  2. Git 폴더의 절대 경로를 입력합니다. 기준 브랜치는 비워 두면 서버 PC에 있는 develop → main → master → 현재 브랜치 순으로 선택합니다.
  3. 직접 입력할 때는 main·master·develop·staging 또는 소문자 type/description 형식을 사용하세요. 예: temp/ai-qa-testing, fix/api/login. 잘못된 이름은 확인 창을 열기 전에 안내합니다.
  4. 다른 기준이 필요하면 로컬 브랜치명을 직접 입력하세요. 없는 이름이면 위 우선순위의 기준 커밋에서 새 로컬 브랜치를 생성합니다. 기존 브랜치와 파일은 변경하지 않으며 원격 push도 하지 않습니다. 커밋 SHA는 입력할 수 없습니다. 기본 후보와 현재 브랜치가 모두 없으면 기존 브랜치를 직접 지정하거나 먼저 준비해야 합니다. 최신 미커밋 파일은 작업 입력에서 제외됩니다.
  5. 프로젝트 등록을 누르면 입력 형식을 검사한 뒤 프로젝트 생성 확인 창이 열립니다. 이름·경로·브랜치를 확인하고 예를 누르세요. 아니오 또는 Esc는 입력을 유지하고 취소합니다. 등록만으로 코드를 수정하거나 원격 발행하지 않습니다.

등록 후 할 일

  1. 프로젝트 상세의 작업 정책·검증 명령에서 수정 허용 범위를 확인하고 필수 검증을 등록합니다. ‘준비 필요’는 등록 실패가 아니라 설정이 남아 있다는 뜻입니다. 검증 명령은 프로젝트별로 다르므로 관리자에게 확인하고, 임의 명령을 복사해 실행하지 마세요.
  2. AI에서 Docker·Codex 로그인과 목적별 모델 검증을 확인합니다. 작업은 프로젝트별 워크트리와 컨테이너에서 진행하며 외부 네트워크를 사용할 수 있습니다.
  3. 함께 사용할 매니저에게 계정·프로젝트 할당을 합니다. 관리자 본인만 사용한다면 생략합니다.
  4. 프로젝트의 문제 상담·내 요청에서 원하는 변경을 설명합니다. 명세 확인과 수정 작업 시작은 별도 단계입니다.

등록이 안 될 때

경로 오류라면 서버 PC에 실제 폴더가 있는지, Git 최상위 폴더인지 확인하세요. 기준 버전 오류라면 해당 로컬 브랜치와 커밋이 있는지 확인하세요. GitHub URL·홈 폴더 전체·앱 데이터 폴더는 등록 대상이 아닙니다.
